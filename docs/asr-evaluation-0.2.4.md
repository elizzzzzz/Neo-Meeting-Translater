# 0.2.4 中日长段自然语音实测

测试日期：2026-11-04；本机 Apple M3、16GB 统一内存。全部识别和翻译在本机完成。下载公开录音，没有上传用户录音。原生 App 的回放由独立测试客户端通过本机 WebSocket 送入，不经过麦克风；不能据此宣称腾讯会议、Teams 或麦克风采集已经验收。

## 实际修复的两个漏句原因

1. **音频缓冲淘汰**：旧版翻译完成后才确认收包，前端只保留最近 4 秒。新版先写入本机临时缓冲并确认收包，识别与翻译分别推进；积压时合并过时的临时识别/翻译版本，完整历史音频仍逐段处理。
2. **轻声误判静音**：AISHELL-4 中 89.06–94.60 秒的清晰中文片段，原始音量约 -41dBFS，被 Silero 拒绝；绕过检测直接识别能正确得到“工作的一些情况先进行一下汇报”。检测输入放大 4 倍后通过，原音频识别结果保持一致。新版只对检测器输入做最大 4 倍的有限增益，保留原始波形和静音/噪声防护。真实片段、纯静音、固定种子的随机噪声回归通过。

原生采样还发现新会话会重新加载语音检测器；新版复用已预热的检测器，在确认所选语言准备完成后才开启麦克风，允许取消准备。语言解码配置仍互相独立。

另修复了逐包四舍五入导致的会议时钟漂移，改为采样总数计时；原文约每 600ms 请求刷新，译文在本机模型生成时逐步显示。架构与故障边界见 [流式处理说明](streaming-architecture.md)。

## 方法

原生 0.2.4 arm64 包已实际加载 SenseVoice、语音检测、声纹及本机 Ollama `translategemma:4b`，保持热启动。质量和时延回放使用锁定中文/日语、200ms PCM16/16kHz 单声道小包，按单调时钟真实播放速度连续送入 App。服务确认所选语言准备完成后才开始计时；评分和文本匹配在播放结束后进行，单独记录送包迟到时间。两个语言的最终回放顺序执行；测试期间未并行运行其他模型测试或构建，但未关闭用户其他程序。

为隔离语音转文字问题，回放配置**关闭自动分人**，不提供说话人错误率结论。真实使用开启分人还会增加开销；多人重叠语音、真实姓名、会议回环和麦克风仍需独立验证。

CER 使用标准编辑距离：替换、删除、插入数之和除以参考字符数。做 NFKC、去标点/空白、大小写规范，中文另做繁简转换，同时保留原字形分数；不统一汉字数字与阿拉伯数字，也不删口头语。因此 CER 不能直接转换成“准确率 = 100%-CER”。

字幕原文时延用参考行末尾 8–12 字的精确匹配估算，相对该行结束时间计时。只统计匹配成功的行，必须查看匹配覆盖率；错误/未匹配的行不会进入分布。另记录最后一次修订后持续可见的估算时延。这里不是人工逐词对齐的严格延迟，也不代表未匹配行的延迟。

译文计时从对应原文版本首次显示开始；统计样本是模型处理的原文修订版本，并不等于独立句子数。分别统计第一段生成内容可见、完整生成完成。第一段可能只是较短文字，不能等同于整句话翻译完成。`received_samples == processed_samples` 和 `dropped_samples=0` 只证明传输/排队没有淘汰，不能证明模型没有漏字。

中文完整回放可接近约 1 秒原文、再约 1 秒首段译文的典型值，但高分位仍会超时；完整译句通常更慢。不能保证“原文约 1 秒、译文再约 1 秒”在所有发言和机器负载下稳定成立。保持完整音频优先，队列真实延迟直接显示，不再通过跳过发言制造实时观感。

## 识别引擎对比

同一录音按 20 秒分块，单次离线解码，仅对比输出质量，**不能拿其解码时间当作字幕延迟**：

| 材料 | SenseVoice int8 CER | Whisper large-v3-turbo 8bit CER |
| --- | ---: | ---: |
| 中文 AISHELL-4 180 秒 | 8.90% | 23.59% |
| 日语国会问答 192.57 秒 | 11.02% | 8.79% |

这两个文件说明不同语言和录音条件需要分别评估，不能一概认定较大的 Whisper 更适合中文。它们也不是独立、广泛的准确率排行榜。当前保留用户的引擎和模型设置，未自动替换模型。日语 Turbo 的长块结果更好，适合下一轮作为日语准确性候选；尚不能推导为它能满足约 1 秒的流式延迟，当前未据此自动替换用户设置。

## 回归与交付检查

67 项 Python 测试（包括本机真实轻声、静音及噪声回归）、21 项前端测试通过。慢翻译不阻塞收音、全部采样处理、过时临时识别合并、停顿前短句、换人边界、停止尾句、译文逐步显示、翻译流异常和积压状态显示均有回归覆盖。没有对应真实模型/录音时，轻声集成测试会跳过，单元测试不自动下载数据。

ZIP 解压、DMG 挂载、arm64 和严格代码签名检查通过；实际原生包加载模型与单实例检查通过。前述中文 403 秒和一次并行诊断负载下的日语回放也完成收尾、未淘汰音频；该日语压力回放曾出现约 30 秒排队，保留在 JSON 中，不用它宣称正常延迟达标。

## 复现

需本机已连接模型、安装 `ffmpeg`，以及开发环境可用的 `websockets`；中文繁简规范可选安装 `opencc-python-reimplemented` 到评估环境，不属于 App 推理依赖。

```bash
python scripts/download_evaluation_audio.py --language zh-meeting --output-dir /private/tmp/local-meeting-evaluation
python scripts/download_evaluation_audio.py --language ja --output-dir /private/tmp/local-meeting-evaluation
# 打开本地 App 并等待模型状态为可用后运行：
PYTHONPATH=src python scripts/evaluate_streaming.py \
  /private/tmp/local-meeting-evaluation/zh-meeting-manifest.json \
  --model /你的模型目录/asr/sensevoice --ws-url ws://127.0.0.1:8000/ws \
  --translate --simplify-chinese --output /private/tmp/zh-result.json
```

不加 `--ws-url` 可直接测试源码中的本机处理流程；加 `--engine whisper --model /本机Whisper模型路径` 可单独测试已连接的 Whisper。日志和完整时间线留在本机评估目录。摘要见 [评估 JSON](evaluations/streaming-0.2.4.json)。
