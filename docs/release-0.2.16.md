# 0.2.16 — Apple 本机语音识别

新增可选的 Apple SpeechAnalyzer 引擎。兼容 macOS 26+；较旧系统仍可选择其他识别引擎。交付包包含 arm64 Swift 原生组件，不需要客户安装 Xcode。

## 使用方法

1. 在主界面选择中日、中英或英日会议语言。
2. 打开“本地设置”，在“语音识别”卡片中选择“Apple SpeechAnalyzer · Apple 本机语音识别”。
3. 查看中文、日语、英语资源状态。点击“准备 Apple 语言资源”仅准备当前会议语言对，首次下载需要联网。刷新列表或启动 App 不会下载资源。
4. 保留或选择独立的本地翻译引擎，保存设置并重开 App。资源缺失时显示具体原因，并阻止开始收音。
5. 自动模式会比较当前语言对的识别候选。判别不明确时提示使用顶部源语言按钮，可随时锁定中文、日语或英语。

Apple 语言资源由 macOS 管理，不使用自定义模型目录，不能通过本 App 移动。语音识别在本机执行，翻译由所选本地翻译模型完成。Apple 引擎不会承担文字翻译，也不会在失败时切换到云端。

## 运行行为和限制

- 使用常驻原生组件和系统模型保留策略。启动时仅预热已安装资源，会话开始前准备所选语言；失败的实时语言切换保留原有识别器与发言记录。
- 对接现有音频窗口、说话人段落、固定双栏和字幕浮窗。单段原生识别请求限制为 4.3 秒，超时终止组件，后续请求重新启动，避免过期结果混入字幕。
- Apple 接口按指定语言识别。当前双语自动判别是应用层候选比较实验功能，置信度不能视为跨语言校准后的准确率；短句、汉字重叠或混合语言可能无法明确判别。候选不明确时不猜测字幕，提示用户锁定源语言。
- 当前实现复用现有有界音频窗口，输出原生最终结果；没有宣称实现 Apple 原生持续流式转写，也未证明满足约 1 秒识别延时目标。

## 验证

- 142 项 Python 测试通过，1 项跳过：覆盖资源缺失、设置保存、当前语言对路由、模糊候选拒绝、时间戳完整性、超时后重启、原生报错后的进程复用和语言切换失败恢复。
- 53 项前端测试通过；模拟资源准备接口的 Chromium 检查覆盖实际选择和按钮操作，以及中、日、英界面在 1440×900、1280×720、1024×768 的布局，没有页面脚本错误或整页溢出。
- 在本机 macOS 26.6.2 上编译并运行只读资源检测，确认系统支持且组件标识正确。检测时中文、日语、英语资源均未安装；没有下载语言资源、录制麦克风或修改真实用户配置。
- arm64 免安装 ZIP 解压与 DMG 挂载检查通过，App 和原生组件的可执行权限、架构与签名有效。交付 App 版本为 0.2.16，内嵌界面与源码一致；打包后的原生组件只读检测也通过。
- 因本机缺少语言资源，尚未实测该引擎的中文/日语准确率、真实会议收音和端到端延时。界面截图与模拟测试结果不代表真实识别效果。

开发环境可先运行 `bash scripts/build_apple_speech.sh`，再按原方式启动 App。资源准备必须通过显式操作执行。
