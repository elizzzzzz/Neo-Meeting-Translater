# 0.2.2：中文锁定与错误字幕修复

选择中文后仍输出 `Thank you`、`Bye` 等英文，根因之一是预热语音模型使用自动识别，会议会话复用这个实例时没有应用所选语言。现在每个会话保留独立的语言和上下文设置，继续复用已预热的模型权重。服务端会返回实际生效的语言，界面显示“已锁定中文”；录音期间锁定输入和语言选项，停止后再更改。

静音、直流偏置和短促点击声不再直接触发识别。音频缓冲限制在四秒内，较长停顿后清理上一轮内容；不足一个识别窗口的短句会在停顿后刷新一次。模型输出需通过无语音概率、解码置信度和重复度检查。固定中文/日语时，与对应文字类型不符的结果会被忽略，并在诊断中解释，不进入翻译。中文句子中的 Teams 等英文名称仍保留。纯英文句子需要切换到英语或自动识别。

麦克风授权后重新读取设备列表，优先显示实际采集轨道的名称。右侧增加输入电平与识别语言；电平只表示收到声音，不代表已识别出有效语音。Ollama 的服务端错误保留具体信息，例如模型进程 `bus error`，不会被笼统显示为无法连接，也不会被已加载模型列表覆盖成正常状态。

验证：34 项 Python 测试、9 项前端逻辑测试；1440×900、1280×720、1024×768 单屏布局、字幕演示与浮窗检查。使用已有本地 `whisper-medium-mlx-8bit`、16 kHz 单声道中文测试录音及合成静音、随机噪声、低频嗡声实测：中文录音输出中文，四种非语音输入均无文字；真实 WebSocket 链路完成中文识别与 Ollama 日文翻译，静音帧不新增字幕。最终打包后的原生 App 也完成了独立复验：冷启动就绪、服务端确认 `asr_language=zh`、中文原文与日文译文返回、静音不新增字幕，且收到音频处理确认。可用以下命令复验（只使用已缓存模型，WAV 不提交到仓库）：

```bash
HF_HUB_OFFLINE=1 PYTHONPATH=src python scripts/verify_live_recognition.py --audio /path/to/chinese-16k-mono.wav --ollama
```

上述实测为录音回放，不代表现场麦克风、腾讯会议、Teams 或多人区分已经完成实测。短窗口仍可能误识别个别词，需继续以真实会议录音评估；本次修复重点是语言设置一致性及非语音产生错误字幕的问题。

发布方式仍为免安装 ZIP 和 arm64 DMG；程序与模型独立，模型权重不包含在发布包内。构建过程在复制交付包前清理重复构建目录，降低临时磁盘需求。

原生启动校验还发现并修复了 MLX GPU 资源路径问题：打包后动态库移到 Frameworks，GPU 资源留在 Resources，需保留两者之间的相对链接。发布校验现在检查这条资源链接，防止语音模型预热时直接崩溃。

运行中还验证了停止录音与模型推理的并发情况：关闭连接不再被误报为识别失败。音频发送等待服务端确认，推理较慢时合并最近音频，防止数据积压导致连接超时；待处理音频最多保留四秒。超出时界面明确提示已跳过多少秒积压，高负载下可能因此漏掉较早的语音，此模式优先保持实时。
