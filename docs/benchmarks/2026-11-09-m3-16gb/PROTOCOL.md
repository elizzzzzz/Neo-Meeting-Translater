# 中日英科技企业会议翻译评测标准 v1

日期：2026-11-09。机器：Apple M3，16 GiB 统一内存。

## 范围与冻结

平台：Ollama、SGLang 的原生 MLX 后端、llama.cpp Metal。后端版本和模型文件版本固定并留存。SGLang 的结果必须来自实际 SGLang 服务，不能用 mlx-lm 直接推理冒充。

模型范围为候选清单中公开可获取的主要 4B、7B、8B 级别指令、专用翻译和视觉语言模型。排除嵌入、重排序、纯代码、纯语音、基础预训练、重复改名和同一权重的重复社区转换。模型的语言覆盖和实际参数量明确列出；不能声称穷尽互联网上所有微调模型。新版本视为不同模型，量化视为同一模型的不同测试配置。

本次只测试 4bit＋8bit：GGUF Q4_K_M、Q8_0；MLX affine 4bit、8bit，group size 优先 64。它们不是位级相同的量化算法；平台对比必须区分格式差异。Ollama 与 llama.cpp 优先复用完全相同的 GGUF 文件，记录 SHA256。

先完成语料、参考译文、评分规则和候选清单，再开始模型输出采集。语料文件写入 SHA256 清单；不能在看到输出后修改参考答案来迎合模型。

## 标准场景

24 个三语平行情境：12 个正式、12 个非正式。每个情境具有中文、日文和英文的等义原文及参考译文，覆盖中→日、日→中、中→英、英→中、日→英、英→日，总计 144 个请求／配置，每个方向 24 例，正式和非正式各 12 例。

题材覆盖 SLA、灰度发布、合同报价、隐私、行动项、故障通报、重试幂等、实验指标、数据授权、跨公司协商、时区、检索与认证，以及合并代码、模糊指代、保留意见、婉拒、术语和口语表达。重点检查否定、条件、承诺强度、时间、金额、百分比与百分点、专有名词、礼貌与语域。

每题附预先写定的原子事实核对清单。参考译文只提供一种正确表达；允许合理同义、语序调整和不同自然表达。没有多模态输入，翻译质量排名只评价文本任务。

## 推理条件与速度

单请求、串行，温度 0，固定 seed（平台支持时），上下文 2048，最大输出 384 token。禁用可配置思考模式，要求只输出译文。不使用投机解码。允许平台原生的跨题 KV 前缀缓存，固定题序，完整保留 raw 输出、模板、请求和返回 token／缓存计数。此项在正式采集前修订：已安装 Ollama 固定发送 cache_prompt=true，故三个平台均启用原生缓存，不能把该结果描述为无缓存测试。各后端缓存实现仍有区别。

llama.cpp 与 Ollama 都指定 CPU 线程 4、batch／microbatch 128。SGLang 使用其原生 MLX 调度和 chunked prefill 256。模型模板先用发布者 tokenizer 编码；llama.cpp／SGLang 传入 token ID，Ollama raw 模式传入等价文本，并根据模型设置移除由后端自动插入的首个 BOS。预热核对完整输入 token 数，防止重复 BOS。客户端 token 化发生在计时之前；Ollama 内部 token 化包含在请求耗时中，此差异如实保留。

通用模型采用相同英文翻译指令，明确源语言、目标语言及正式／非正式会议语境。专用翻译模型允许使用发布者要求的模板，并明确记录，不能因错误模板把可用模型误判为差。少样本提示和针对单题调优不允许。

每个配置先预热一次，不计入速度。逐题记录首 token 延迟（TTFT）、端到端耗时、输出 token 数、平台报告 decode TPS、实际输出字符数，以及整轮内存／交换区采样。单题 60 秒无进度或总时长 120 秒可中止并记失败；内存不足不得反复强行重试。异常须保留原始日志。

跨 tokenizer 的 token/s 不直接当作可比的工作量。跨模型速度排名采用每个方向的“源文 Unicode 字符数／端到端时间”，再对六个方向等权汇总；同时报告平均／中位／P95 延迟和平台 decode TPS。下载和首次加载时间单独报告，不计入热推理延迟。

进程 RSS、系统可用内存和系统交换区分别采样。MLX 分配量仅在后端实际暴露该指标时报告，缺失时不以 RSS 替代；当前驱动直接采样的是进程树 RSS 与整机内存／交换区。不同指标不相加、不混称独占显存。Apple Silicon 使用统一内存。

## 准确性与盲评

不把 BLEU／chrF 或字面相似度称为准确率。自动标记空输出、思考标签及疑似截断，只供复核。数字、术语、目标语言和原子事实由本助手按预写清单逐项核对，不将简单字符串匹配当作语义准确性。

主质量分按每题四个维度评分，每项 0–5，可使用 0.5 分：

| 维度 | 权重 | 依据 |
|---|---:|---|
| 意义完整与忠实 | 50% | 原意、否定、条件、主客体、确定性、增译漏译 |
| 技术与商务术语 | 20% | 概念准确，专名一致，不能字面误译 |
| 数字、实体与事实 | 20% | 金额、日期、时区、比例、版本和行动负责人 |
| 自然程度与语域 | 10% | 目标语自然，正式／非正式语气匹配 |

题分 = 10×意义 + 4×术语 + 4×事实 + 2×语域，范围 0–100。执行失败或空输出记 0 分。因平台不支持而未执行的配置标记“不支持”，不能伪造为翻译质量 0 分。

另报告“原子事实准确率”：逐条标记正确、部分正确、错误，分别计 1、0.5、0；总得分／可评事实数×100%。必须逐项复核，不允许用总体印象编造百分比。错误否定、错误数字／单位、条件变承诺等单独标记关键错误，并提供例句。

评审包用随机配置编号隐藏模型、平台和量化名称，逐题评审后才连接身份映射。由本助手按固定参考译文与清单评审；这是标签隐藏的模型辅助评审，不冒称独立母语译者或外部人类盲审。质量分保留理由和错误证据。不能用另一个本地模型的未经审查打分代替。

评审者已参与测试准备，首批只有一个独立检查点时可能从对话上下文推断模型家族；因此不声称严格双盲或完全消除身份偏差。逐项原子事实、错误原句和维度评分均保留，方便后续人工复核。同题精确相同的输出去重评审，以指纹关联到各配置；历史评审包保留SHA256快照。

为在采集期间继续评审，可将已落盘且以换行结束的逐题记录加入标签隐藏评审包；未写完的末行留到下一次快照。未完成配置即使部分题目已经评审，仍不得入榜。完整配置必须额外核验144条记录、输出文件SHA256和全部评审覆盖；校验记录保存在results/review-audit.json。

## 排名

分别报告：六方向质量、正式／非正式语域、模型及量化平均质量、4bit 对 8bit 的质量／速度差异、同一 GGUF 的 Ollama 对 llama.cpp 平台差异、SGLang 格式差异和失败／不支持矩阵。

综合分 = 翻译质量×0.85 + 速度分×0.10 + 稳定性分×0.05。速度分以完整有效配置中最快的六方向归一化吞吐为 100；稳定性分为成功完成题目比例×100。质量为各方向题分均值再六方向等权平均。所有入榜配置必须完成题目核对和盲评；未完成的配置显示待测／待评，不发布虚假完整排名。

多模态分别记录：模型原生文本／图片／音频／视频能力、转换文件是否保留编码器／投影器、当前后端实装支持、是否实际测试。本项目未实际测试图片／音频时必须写“未验证”，不能凭模型卡声称实测通过。多模态能力不计入纯翻译综合分。

## 磁盘与清理

已按用户要求删除旧的 Qwen3.5-4B 与 Qwen3.6-27B。保留原有、无关的 Ollama 语音模型。

每次只加载一个模型配置；完成该配置在适用平台的测试、落盘输出和校验后，卸载并删除本轮权重，再下载下一配置。评测用独立缓存和带前缀的 Ollama 名称；只删除清单精确标记的本次权重、模型条目和临时转换文件，绝不全局 prune。结果、元数据、校验和、日志和评分保留。启动前估算文件及导入副本大小，磁盘不足时不下载。

从TranslateGemma Q8_0开始，临时HF和Ollama权重改放在本机 `/private/tmp/codex-translation-benchmark-9c6152d3c717941d/`，以项目路径生成隔离名称并用owner.json核对所有权。此前文稿目录存在iCloud文件提供器标记；此次迁移避免临时权重位于该目录，不能据此断言此前磁盘下降由iCloud造成。语料、评分、结果与运行版本均保留在原项目。迁移时该Q8_0文件尚未进入推理；中断后的下载器未保留权重断点，需重新下载这一文件，详见results/storage-migration.json。

后续Ollama导入将已校验GGUF以同卷硬链接放入本次独立store，并核对相同inode；避免权重双份占用。链接在Ollama服务启动清理结束后创建，模型删除只移除该链接，全部平台结束后再删除原始缓存。空间预算为唯一权重加5 GiB余量；前两次GGUF平台试运行使用普通导入，其推理输入不受该存储方式变化影响。

失败可在明确修复参数／兼容性原因后重试一次；不能静默换成不同模型或不同后端。每个配置独立状态，支持中断后从已验证结果恢复。

Qwen3.5的SGLang MLX启动默认选择extra_buffer，但已安装平台不支持Mamba状态快照。显式no_buffer与disable_overlap_schedule通过本机参数解析验证，后续使用这两个公开参数进行一次实际重试；保留最初失败日志，实际推理成功与否另行记录。该参数选择保留原生前缀缓存，不修改SGLang库或模型权重。证据与重试控制记录见results/diagnostics/qwen35-sglang-mamba/。

Qwen3.5 MLX4在上述参数修复后完成实际启动尝试，后续在前缀缓存匹配中触发MlxAuxiliaryStateComponent缺少host_only_checkpoint的AttributeError，未产生评分题输出；此为已安装SGLang管线兼容失败，不是底模翻译0分，也未证明OOM。MLX8第一次参数修复尝试因评测tokenizer目录漏图像处理器配置而中止，该次属于评测脚本准备遗漏，保留原始日志并安排补齐元数据后的同权重重试。视觉检查点的小型processor/preprocessor配置从冻结转换修订补齐并保留SHA256，不改变权重、文本模板或测试语料；未因此声称完成图像推理。对应证据见results/processor-metadata-preparation.json和results/diagnostics/qwen35-sglang-mamba/runtime-diagnosis.json。

Qwen3.5 MLX8补齐处理器后的重试已于11:16完成：不再出现缺少图像处理器配置错误，但与MLX4相同，在缓存匹配阶段触发host_only_checkpoint缺失。未产生评分题输出，权重已删除验证。父进程记录的退出码不单独作为OOM证据；以原始子进程AttributeError和日志SHA256记录实际失败位置。
