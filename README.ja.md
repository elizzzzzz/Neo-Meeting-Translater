# NMT · Neo Meeting Translater

**NMTは音声認識も翻訳もすべてローカルで実行できます。モデルの準備後は、会議の音声や文字をクラウドに送信せず、Mac上で中国語・日本語・英語の発話をオフラインで認識し、二言語字幕を生成できます。**

[English](README.md) · [简体中文](README.zh-CN.md) · [最新版をダウンロード](https://github.com/elizzzzzz/Neo-Meeting-Translater/releases/latest) · [ライセンス](LICENSE)

## NMTでできること

NMTは1つの音声入力を受け取り、発言を文字にして、原文と翻訳を並べて表示します。対面会議、Tencent Meeting、Microsoft Teams、Web動画に利用できます。

ローカルの音声認識モデルと翻訳モデルを選べば、音声・文字・モデルはMac内で処理されます。現在のバージョンは文字字幕を中心に提供しており、翻訳音声の読み上げはまだ対応していません。

現在のバージョン：**v0.2.21** · Apple Silicon Mac（arm64）· macOSネイティブアプリ

## 主な機能

- 中国語 ↔ 日本語、中国語 ↔ 英語、英語 ↔ 日本語。
- 選択した言語ペアの中で発話言語を自動判定。
- 判定が違うときは、中国語・日本語・英語のボタンですぐに指定。
- 同じ話者の発話を段落として保持し、認識結果を修正しながら原文と翻訳を表示。
- 履歴をスクロール表示。話者ラベルは匿名で表示できます。
- 半透明の字幕ウィンドウを常に手前に表示、移動、サイズ変更できます。原文だけ、翻訳だけの表示も可能です。
- 画面表示は中国語・日本語・英語に対応。
- ライト、ダーク、システムに合わせる外観。
- 翻訳はOllama、llama.app、SGLangのローカルサービスに対応。
- 音声認識はApple SpeechAnalyzer、MLX Whisper、SenseVoiceに対応。
- モデルの状態、Ollamaの接続状態、初回読み込みの進み具合、入力音量を表示。
- 設定を保存するとすぐ反映され、アプリを再起動する必要はありません。

## ダウンロード前の準備

必要なもの：

- Apple Silicon Mac。現在のパッケージはarm64用で、Intel Macには対応していません。
- macOSのマイク許可。
- 音声認識エンジンとモデル。Apple SpeechAnalyzerはmacOS 26以降、WhisperとSenseVoiceはローカルモデルファイルを使用します。
- ローカル翻訳サービス。多くの方にはOllamaをおすすめします。
- Tencent Meeting、Microsoft Teams、Web動画、ローカル動画の音声は、NMT内蔵のmacOSシステム音声取り込みを使用できます。互換用の仮想オーディオデバイスも選べます。

アプリ本体にモデルファイルは含まれていません。ダウンロードを小さくし、保存場所を選べるようにするためです。

## ダウンロードと起動

1. [最新版のリリースページ](https://github.com/elizzzzzz/Neo-Meeting-Translater/releases/latest)を開きます。
2. インストール不要なら **NMT-portable.zip** をダウンロードし、解凍して **NMT.app** をダブルクリックします。
3. 通常のインストールは **NMT.pkg** をダウンロードし、ダブルクリックして macOS の手順に従います。
4. または **NMT.dmg** を開き、**NMT.app** を「アプリケーション」ショートカットへドラッグします。
5. 「アプリケーション」から NMT を起動し、初めて音声を取り込むとき macOS のマイク許可を認めます。
6. NMTはブラウザではなく、独立したMacウィンドウで起動します。

リリースには **NMT-0.2.21.sha256** も含まれます。確認する場合は、チェックサムファイルをZIP、DMG、PKGと同じフォルダに置き、ターミナルで実行します。

~~~bash
shasum -a 256 -c NMT-0.2.21.sha256
~~~

現在のインストーラは Apple Developer ID による署名および Apple の公証を行っていません。`NMT.pkg` または `NMT.app` を初めて開く際に、開発元や安全性を確認できないと表示された場合：

1. 一度ファイルを開こうとして、警告を閉じます。
2. **システム設定 → プライバシーとセキュリティ** を開き、「セキュリティ」までスクロールします。
3. NMTの警告の横にある **このまま開く** を押し、パスワードまたは Touch ID で認証して「開く」を確認します。
4. インストーラを許可した場合は、インストール後にNMTを開きます。アプリもブロックされた場合は、同じ手順で許可します。

NMTだけを許可すればよく、システム全体のセキュリティを無効にする必要はありません。ZIPから解凍したアプリも同じ初回起動手順を使います。

## 話者の判別と段落

「自動話者分離（テスト）」を選ぶと、ローカルの声紋モデルで異なる声を判別します。モデルがない場合はこの項目を選択できないため、「手動で話者変更」を使ってください。話者ラベルは実名を識別するものではありません。

声の変化が確認されたときに新しい段落を作り、同じ話者が間を置いて話し続けた場合は元の段落を保ちます。自動判別には一定量の音声と複数回の確認が必要です。短い相づち、似た声、同時発話は誤判定されることがあり、人が確認した議事録の代わりにはなりません。

## 初回設定

1. 「設定」を開きます。
2. 「音声認識」でApple SpeechAnalyzer、Whisper、SenseVoiceのいずれかを選びます。
3. 「翻訳」でOllama、llama.app、SGLangのいずれかを選びます。
4. 中国語–日本語、中国語–英語、英語–日本語の言語ペアを選びます。
5. Macのマイク、またはオーディオループバック入力を選びます。
6. 「保存して戻る」を押します。
7. 音声認識と翻訳モデルが「利用可能」になってから「開始」を押します。

モデル、サービス、モデルフォルダ、言語ペア、外観はいつでも変更できます。保存後すぐに反映され、再起動は不要です。既存モデルのファイルは自動で移動しません。

## Ollamaの設定

Ollamaはローカル翻訳に最も簡単な選択です。NMTはこのMacの **http://127.0.0.1:11434** に接続します。

### インストールして起動

[ollama.com](https://ollama.com/download/mac)からOllamaをダウンロードし、Macアプリを開いたままにします。NMTの設定画面にも「Ollamaをインストール」ボタンがあります。

ターミナルで確認します。

~~~bash
ollama --version
ollama list
~~~

ollama listでモデル一覧が表示されれば、通常は利用できます。NMTの設定で「再チェック」を押し、「インストール済み」「接続済み」と表示されることを確認します。

### メモリと測定結果から翻訳モデルを選ぶ

以下は **M3 / 16 GiB** と **M5 / 32 GiB** のテキスト翻訳テストです。品質、待ち時間、メモリの余裕を比べて選んでください。同じメモリ容量でも、チップが違えば速度は変わります。掲載する各構成は、中日・中英・英日の双方向、計144問を完了しています。

総合点は品質85%＋速度10%＋収集完了率5%です。同じテスト内の比較に使い、2台の総合点を直接順位付けしないでください。品質点は固定の参考訳と事実チェックリストを用いた、同じ条件で構成を比較するための参考値です。**音声認識の正解率やすべての会議での結果を保証するものではありません**。

| モデル・精度・サービス | 総合 /100 | 品質 /100 | 平均 TPS | 全文の中央値（秒） | P95 遅延（秒） | 最大 RSS（GiB） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Qwen3-4B-Instruct-2507 Q4_K_M · llama.cpp | 92.59 | 92.29 | 31.56 | 1.59 | 2.19 | 3.11 |
| Qwen3-4B-Instruct-2507 Q4_K_M · Ollama | 91.56 | 92.29 | 29.51 | 1.79 | 2.60 | 3.18 |
| Qwen3-4B-Instruct-2507 4bit · SGLang MLX | 90.42 | 92.40 | 30.70 | 1.61 | 6.22 | 4.59 |
| Hy-MT2 7B Q4_K_M · llama.cpp | 90.01 | 95.26 | 16.79 | 3.32 | 6.70 | 6.64 |
| Qwen3.5 4B Q4_K_M · llama.cpp | 89.66 | 93.44 | 21.35 | 2.30 | 4.89 | 4.40 |
| Qwen3 4B Q4_K_M · Ollama | 87.34 | 90.18 | 20.58 | 2.64 | 3.85 | 3.09 |
| TranslateGemma 4B Q8_0 · Ollama | 83.41 | 85.85 | 20.92 | 2.73 | 3.42 | 4.62 |
| TranslateGemma 4B Q4_K_M · Ollama | 81.38 | 87.24 | 9.50 | 5.95 | 11.26 | 3.02 |

- **字幕の速度を重視**：Qwen3-4B-Instruct-2507 Q4_K_Mが候補です。Ollamaは設定しやすく、この測定ではllama.cppが速い結果でした。通常の `qwen3:4b` とは別のチェックポイントです。
- **翻訳品質を重視**：Hy-MT2 7B Q4_K_M / llama.cppは品質95.26、全文遅延の中央値3.32秒でした。同モデルのOllamaは11.74秒のため、llama.cppの速度をOllamaに当てはめないでください。
- Qwen3.5 4B Q4_K_M / llama.cppも比較候補です。TranslateGemma 4Bは比較用に掲載し、標準候補とはしていません。TranslateGemma 12BとQwen2.5 3Bはこの表の測定対象外のため、比較結果には含めません。

実用的な構成を掲載しています。[16Gの全結果・条件](docs/model-benchmark-2026-11-09-m3-16gb.md)と[構成別の遅延・メモリ記録](docs/benchmarks/2026-11-09-m3-16gb/configuration-metrics.csv)も参照してください。

| Qwen3.5 9B Q4_K_M · Ollama | 91.37 | 96.25 | 21.81 | 2.32 | 3.19 | 7.94 |
| Qwen3.5-4B 8bit · SGLang MLX | 89.38 | 93.58 | 21.56 | 2.16 | 3.11 | 7.48 |
| Qwen3-8B 4bit · SGLang MLX | 89.28 | 92.83 | 26.40 | 1.88 | 2.67 | 6.55 |

| Qwen3-8B 8bit · SGLang MLX | 87.00 | 92.81 | 14.39 | 3.33 | 4.77 | 5.49 |

- **品質と音声認識・会議アプリ用の余裕を重視**：Qwen3.5 9B Q4_K_M / Ollamaから試せます。この測定で品質点が最も高く、全文遅延の中央値は2.32秒でした。
- **速度を重視しメモリに余裕がある場合**：Qwen3 30B-A3B Q4_K_M / Ollamaが候補です。中央値1.03秒ですが、最大RSSは17.67 GiB、システム全体のswap最大値は1.47 GiBでした。A3Bは3B分の重みだけを読み込めばよいという意味ではなく、16G向けの推奨ではありません。
- **SGLang MLXを利用中の場合**：Qwen3.5 4B 4bitが低遅延候補です。本測定は互換パッチを使用し、全体のswapは最大10.46 GiB（8bitは11.91 GiB）でした。負荷を整理して再確認してください。RSSだけで十分な空き容量があるとは判断できません。

実用的な7構成を掲載しています。[32Gの全報告](docs/model-benchmark-2026-11-19-m5-32gb.md)と[構成別記録](docs/benchmarks/2026-11-19-m5-32gb/configuration-metrics.csv)には未評価、失敗、低速の構成もあります。9Bと30B-A3Bでもテスト文に誤訳が残る場合があり、高得点でも無誤訳を意味しません。

**数値の見方**：中央値は全文翻訳を待つ典型的な時間、P95は約95%の問題が完了した時間です。TPSは生成速度で、待ち時間そのものではありません。RSSはサービスのプロセス群の常駐メモリ標本で、統合メモリの総必要量ではありません。swapはシステム全体の値です。これは文字翻訳のみの測定です。音声認識、音声入力、字幕表示により実際の会議結果は変わります。llama.cppは直接測定しており、llama.app自体の測定ではありません。サービス・テンプレート・量子化を変える場合は再試用してください。音声認識エンジンは別途選択します。

### 選んだモデルを用意する

16Gで **Qwen3-4B-Instruct-2507 Q4_K_M** を選ぶ場合、そのチェックポイントのGGUF変換をダウンロードします。llama.appに読み込みローカルサーバーを有効にする方法もあります。Ollamaでは `Modelfile` というテキストファイルに実際の保存先を書きます：

~~~text
FROM /full/path/Qwen3-4B-Instruct-2507-Q4_K_M.gguf
~~~

`Modelfile` のあるフォルダで実行します（実際のファイル名を使用し、空白を含むパスは二重引用符で囲みます）：

~~~bash
ollama create nmt-qwen3-4b-2507 -f Modelfile
ollama list
~~~

[元モデルの公開ページ](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507)で確認し、Q4_K_M変換の公開者とライセンスも確認してください。`nmt-qwen3-4b-2507` は自分で作るローカル名で、公開ダウンロードタグではありません。評価には固定のファイルとテンプレートを使用しているため、新しい変換で同じ点数を保証するものではありません。

32Gで以下のOllama構成を選ぶ場合、**選んだモデルのコマンドだけを実行**してください：

~~~bash
ollama pull qwen3.5:9b-q4_K_M
~~~

または：

~~~bash
ollama pull qwen3:30b-a3b-q4_K_M
~~~

NMTの設定で対応する翻訳サービスと `ollama list` に表示される正確なモデル名を選び、「保存して戻る」を押します。初回読み込みは準備完了まで待ってください。これらは利用者が必要に応じて実行するコマンドで、既存モデルを自動で置き換えません。

### モデル保存場所

Ollamaは通常、自分のモデルフォルダを使います。NMTの設定で「Ollamaの現在のフォルダを使用」を押すと検出した場所が入力されます。ASRモデルなどは別のフォルダを選べます。

NMTのフォルダ設定を変えても、Ollamaのモデルは移動しません。Ollama自身の保存先を変えた場合は、Ollamaを再起動してからNMTで「再チェック」を押してください。

### 利用できない場合

1. Ollamaアプリを開き、数秒待ちます。
2. ターミナルで **ollama list** を実行します。
3. NMTのサービスが「Ollama」、アドレスが **http://127.0.0.1:11434** か確認します。
4. 「再チェック」を押します。
5. モデル名が ollama list の表示と完全に同じか確認します。
6. モデルがなければ上記の手順で選んだモデルをダウンロードまたは取り込み、正確なローカル名を選びます。
7. 保存先を変更した直後なら、Ollamaを再起動して再チェックします。

## 会議・動画の音声

1. NMTで **システム音声 / プレーヤー音声** を選びます。
2. macOSの画面と音声の許可で会議またはプレーヤーのウィンドウを選びます。
3. 「開始」を押します。

システム収録が使えないmacOSでは、互換仮想オーディオデバイスを入力として選べます。

原音も聞きたい場合は、macOSの「Audio MIDI設定」でヘッドホンと仮想デバイスを含むマルチ出力装置を作成します。

## 字幕モード

「字幕モード」を押して半透明の浮動字幕を開き、会議画面の空いた場所へ移動します。原文と翻訳、原文だけ、翻訳だけを選べます。過去の段落はスクロールでき、最新の段落は下に残ります。

## プライバシーと制限

- ローカルエンジンを選べば、音声・認識文字・翻訳・モデルはMac内に残ります。
- Tencent MeetingやTeamsのクラウド文字起こしは使用しません。
- 雑音、遠い声、同時発話では認識が誤ることがあります。
- 話者ラベルは匿名で、会議アプリの参加者名は取得しません。
- 遅延はモデル、文の長さ、Macの負荷で変わります。認識約1秒、翻訳追加約1秒は目標であり保証ではありません。
- 現在は文字字幕が中心で、翻訳音声出力は未対応です。
